## Recommended execution order

1. **004 first** — pure accessibility fix, zero visual change in the default
   (non-reduced-motion) experience, touches the most files but is
   mechanical and low-risk. Do this before anything else so later plans
   aren't reviewed against a codebase with a known pending accessibility gap.
2. **005 next** — small, independent, two files, no shared code with
   anything else in this batch.
3. **006 (Lenis) before 007, 008, or 009** — it changes how scrolling itself
   behaves site-wide (via `ScrollTrigger.update` on every Lenis scroll
   event), so it should land and get feel-checked on its own before adding
   more scroll-linked effects on top of it. 007, 008, and 009 will all be
   easier to feel-check correctly once Lenis's inertia is already the
   baseline scroll feel, rather than checking them against native scroll and
   then re-checking after Lenis lands.
4. **007 and 009 next, in either order** — both are single-file, independent
   (`Story.tsx` vs. `Hero.tsx`), low structural risk (motion-only additions).
5. **008 last** — the only plan in this batch that changes layout structure
   (sticky positioning), touches two files, and has the largest feel-check
   surface (both scroll directions, desktop vs. mobile, reduced motion).
   Review its diff more carefully than the others before merging.

004 and 005 have no dependency on 006-009 or on each other. 006 should
precede 007-009 for feel-check ordering reasons above, though none of them
have a hard code dependency on 006 landing first — they'd still work against
native scroll, just feel slightly different to review twice.
